## نظرة عامة على البنية

**الواجهة**: ملف HTML واحد (`index.html`, ~470 كيلوبايت) يحتوي كل شيء — HTML + CSS + JavaScript خام (لا React، لا build step، لا dependencies خارجية). كل الواجهة والمنطق التجاري (صلاحيات، مسارات اعتماد، تقارير...) داخل هذا الملف.

**الخلفية**: PHP خام (بدون framework) + MySQL. لا Composer، لا مكتبات خارجية.

**التخزين**: قاعدة البيانات بأكملها (كل الموظفين، المعاملات، الإعدادات...) محفوظة كـ **كائن JSON واحد ضخم** في عمود `LONGTEXT` بجدول `hr_store`. هذا ليس تصميمًا علائقيًا تقليديًا — بل نمط "مستند JSON" حيث الواجهة تُحمّل الكائن كاملًا، تعدّله محليًا في المتصفح، وترسله كاملًا عند الحفظ.

**لماذا هذا التصميم؟** المشروع بدأ كنموذج أولي (prototype) سريع التطوير، ثم انتقل من نسخة Node.js (تخزّن نفس بنية JSON في ملف على القرص) إلى PHP+MySQL دون تغيير بنية البيانات — فقط تغيّر مكان الحفظ.

### جداول قاعدة البيانات (9)
| الجدول | الغرض |
|---|---|
| `hr_store` | **المصدر الوحيد للحقيقة** — عمود `data` يحوي JSON الكامل |
| `hr_kv` | الصور والمرفقات (base64 داخل JSON بمفتاح مثل `hrsys:photo:2001`) |
| `hr_sessions` | جلسات الدخول (توكن، صلاحية 12 ساعة) |
| `hr_employees`, `hr_requests`, `hr_attendance` | نسخ "مرآة" مُشتقة تلقائيًا من `hr_store.data` بعد كل حفظ، **للاستعلام المباشر بـ SQL فقط** — ليست مصدر الحقيقة |
| `hr_reset_codes` | رموز استعادة كلمة المرور المؤقتة |
| `hr_audit` | سجل محاولات الدخول (للحماية من التخمين) |
| `hr_backups` | نسخ احتياطية تلقائية كل 6 ساعات |

⚠️ **مهم لأي تعديل مستقبلي**: أي حقل جديد يُضاف للموظف/المعاملة يجب إضافته في **JavaScript فقط** (بنية الكائن داخل `index.html`) — لا حاجة لتعديل SQL schema إلا إذا أردت إتاحته للاستعلام المباشر عبر جداول "المرآة" (عندها عدّل `lib/mirror.php` أيضًا).

## نمط عمل الواجهة (مهم لفهم الكود)

```js
let DB = null;   // الكائن الكامل، يُحمَّل مرة عند بدء التشغيل
let ME = null;   // الموظف المسجّل دخوله حالياً (مرجع لعنصر داخل DB.employees)

const save = () => S.set(KEY, DB);   // كل تعديل ينتهي بنداء save()
```

- **القراءة**: `GET /api/db.php` يرجع `{version, db, updatedAt}` — الواجهة تخزّن `db` كاملاً في `DB`.
- **الكتابة**: `PUT /api/db.php` بجسم `{version, db}` — الخادم يرفض بـ **409** إن كانت `version` غير مطابقة للنسخة الحالية على السيرفر (يمنع الكتابة فوق تعديل مستخدم آخر متزامن).
- **معالجة تعارض 409 الحالية**: تسحب نسخة السيرفر الأحدث وتستبدل بها `DB` محلياً (تفقد التعديل المحلي غير المحفوظ). تم إصلاح هذا جزئياً في `saveForcePass()` ليكتشف الفشل ولا يُظهر رسالة نجاح كاذبة — **لكن هذا الإصلاح لم يُعمَّم بعد على بقية دوال `save()`** المنتشرة في مئات الأماكن بالملف (انظر "تحسينات مقترحة" أدناه).

### تسجيل الدخول (`doLogin()` في index.html)
خطوتان:
1. **تحقق محلي أولاً**: يبحث عن الموظف داخل `DB.employees` (المحمّلة مسبقاً) ويقارن كلمة المرور محلياً.
2. **إن نجح محلياً**: يستدعي `serverLogin()` فعلياً لإنشاء جلسة (`POST /api/login.php`) والحصول على `TOKEN`.

⚠️ هذا يعني: **يجب أن يكون `DB.employees` قد تحمّل بنجاح مسبقاً** (عبر `GET /api/db.php` عند فتح الصفحة) قبل أن يستطيع أي أحد تسجيل الدخول أصلاً — فلا "تحقق من الخادم مباشرة" مستقل. راجع `probeServer()` + `pullDB()` في بداية الكود لفهم تسلسل الإقلاع.

## مشاكل معروفة تم إصلاحها مؤخراً (سياق تاريخي)

1. **إخراج JSON ملوّث بتحذيرات PHP** → أُصلح بإضافة `ob_start()` في `lib/helpers.php` مع `ob_end_clean()` قبل كل `json_out()`.
2. **فشل صامت عند تحديث "جداول المرآة"** → دالة `sync_mirror_tables()` كانت تُلتقَط أخطاؤها بـ `catch (Exception $e)` فقط، وهذا **لا يلتقط `Error`/`TypeError`** في PHP 7+. أُصلح بتغييره إلى `catch (Throwable $e)` في `api/db.php` (موضعين: النسخ الاحتياطي التلقائي، ومزامنة المرآة).
3. **فقدان صامت لكلمة المرور عند التعارض** → `saveForcePass()` كانت تستدعي `save()` بدون `await` وتُظهر "تم الحفظ" فوراً بغض النظر عن النتيجة الفعلية. أُصلح بجعلها async تنتظر النتيجة الحقيقية وتتراجع عن التغيير محلياً إن فشل الحفظ فعلياً على السيرفر.
4. **رسالة خطأ مضلِّلة عند فشل تسجيل الدخول** → `serverLogin()` كانت تعيد `false` لأي استجابة `!r.ok`، بما فيها 401 (بيانات خاطئة فعلياً)، فتظهر رسالة "تعذّر الاتصال بالسيرفر" رغم أن المشكلة كلمة مرور غير مطابقة لما هو مخزَّن. أُصلح بتمييز `kind: 'auth'` عن `kind: 'network'`.
5. **الاعتماد على `.htaccess` لإعادة كتابة الروابط** كان يسبب أعطالاً متكررة (404، 403 على النطاق كاملاً) بسبب أخطاء نسخ يدوية متكررة من قِبل المستخدم غير التقني عبر File Manager على الجوال. **الحل النهائي المُطبَّق**: الواجهة تستدعي ملفات PHP **مباشرة بامتدادها الكامل** (`/api/login.php` بدل `/api/login`) — **لا حاجة لأي `.htaccess` بعد الآن**، وقد حُذف من هذه الحزمة عمداً.

## مشكلة مفتوحة حالياً (تحتاج تحقيقاً)

**الموظف `2442061814` (hr_staff) لا يستطيع تسجيل الدخول** — التحقق المحلي ينجح (الكلمة `123456` مطابقة لما في نسخة `DB.employees` المحلية بالمتصفح)، لكن `POST /api/login.php` يرفض بـ 401 فعلياً (تأكد هذا بعد إصلاح رسائل الخطأ في البند 4 أعلاه). **هذا يعني كلمة المرور الفعلية المخزَّنة في `hr_store.data` على قاعدة البيانات مختلفة عن `123456`** — على الأرجح تغيّرت في وقت سابق عبر إحدى دوال `save()` غير المحمية (نفس فئة العلة رقم 3 أعلاه)، ولم يُلاحَظ وقتها.

**الحل المؤقت المُقترح للمستخدم**: استخدام أداة "🔑 إدارة كلمة المرور" (`passManage()` في الواجهة، متاحة لمدير HR من ملف أي موظف) لإعادة ضبطها يدوياً.

**الحل الجذري المُقترح لأي مطوّر يكمل العمل**: تعميم نفس نمط `saveForcePass()` (async + انتظار فعلي + تراجع عند الفشل) على **كل** الأماكن التي تستدعي `save()` بعد تعديل بيانات حساسة (خصوصاً `passApply()`, `saveDone()`, وأي دالة تُعدّل `pass` أو `mustChangePass`). يمكن تسهيل هذا بإنشاء دالة عامة:
```js
async function saveOrAlert(revertFn){
  const ok = await save();
  if(!ok){ if(revertFn) revertFn(); toast('فشل الحفظ — أُعيدت البيانات لحالتها السابقة'); }
  return ok;
}
```
واستبدال نداءات `save();` الحرجة بها.

## تحسينات مقترحة (لم تُنفَّذ بعد)

1. **تعميم إصلاح "الحفظ الآمن"** (أعلاه) على كل دوال `save()` الحرجة، وليس فقط `saveForcePass`.
2. **جداول `hr_employees`/`hr_requests`/`hr_attendance`** تُعاد بناؤها بالكامل (`TRUNCATE` + إعادة إدراج) بعد **كل** حفظ — غير فعّال لقاعدة بيانات كبيرة (800+ موظف). يُفضَّل التحديث الفرقي (diff) بدل إعادة البناء الكامل عند نمو البيانات.
3. **كلمات المرور مخزَّنة كنص صريح** داخل JSON (`emp.pass`) بلا تشفير. للإنتاج الحقيقي، يُنصَح بتشفيرها (`password_hash()` في PHP) — لكن هذا يتطلب تعديل منطق المقارنة في كل من الواجهة (`doLogin`) وE `api/login.php` معاً، وتعديل كل مكان يُنشئ/يُعدّل كلمة مرور.
4. **`api/reset_request.php` و `api/reset_verify.php`** موجودان لكن **غير مستخدَمين فعلياً** من الواجهة الحالية (التي تستخدم مساراً مختلفاً محلياً عبر `sendMail()` العام). يمكن حذفهما أو ربطهما فعلياً لتوحيد المسار.
5. **لا يوجد تشفير TLS مُفعَّل صراحة في الكود** (يعتمد على أن الاستضافة توفر HTTPS) — تأكد أن `https://` مفروضة دائماً (لا مسارات `http://` صريحة).

```bash
h = open('index.html', encoding='utf-8').read()
open('/tmp/check.js', 'w', encoding='utf-8').write(h.split('<script>')[1].split('</scr' + 'ipt>')[0])
"
node --check /tmp/check.js
```
